### 切り分け: MLX の 2 ターン目が崩れる・保存されないことがある（2026-10-21 追加）
症状（iPhone 15、フィードバック ADbZQHomlI8E）: ツール保存の後の 2 ターン目「牛乳を覚えておいて」が 1.2 秒で `će ボタンを覚えておいて` を返し、ツールを呼ばなかった。ユーザー報告では、1 ターン目でも保存されないことがある。フィードバック AL1Kb6E9NDM9（2026-10-20 17:34、iPhone 15）で確認: **新しいセッションの 1 ターン目**「私の名前はケイタ 覚えておいて」が 1.6 秒で `かてに、ケイタ。` を返し、ツールなし（transcript entries=3）。→ 崩れは 2 ターン目に限らない。H2（ツール履歴だけが原因）は単独では説明できない。
ソースで確認した事実（mlx-swift-lm 3.32.3 `MLXFoundationModels`）:
- 毎ターン、トランスクリプト全体を chat メッセージに変換し直してプロンプトを作る（前ターンの KV キャッシュは使い回さない）。ツール呼び出しは `assistant(toolCalls:)`、結果は `tool` メッセージとして Qwen のテンプレートで描画される。
- ツール許可モード（既定 `.allowed`）は制約なしの通常生成で、モデルが `<tool_call>` を出したときだけツールになる。呼ぶかどうかはモデル任せ。
- 生成設定を指定しないと、温度 0.6・top-p 1.0（足切りなし）のランダム選択（`GenerateParameters` の既定値）。1.5B モデルでは低確率の変な語（「će」など）が混じり得るし、呼ぶ／呼ばないが毎回変わる。
仮説（1 つずつ確かめる）:
- H1 ランダム選択のばらつき: greedy にすると崩れが消え、結果が毎回同じになる。
- H2 ツール結果を含む履歴が原因: C（ツール保存の後）だけ失敗し、A・B は成功する。
- H3 モデルの力不足: greedy でも A（1 ターン目）からツールを呼ばないことがある。
手順（iPhone 15、`MLX Qwen2.5 1.5B`、先に「モデルを読み込む」）:
1. 「実験」欄で 生成設定=既定、回数=5 にし、実験 A → B → C の順に「実験を実行」。各実験の最後に `結果 …: ツール呼び出し n/5` が出る。
2. 生成設定=greedy にして A → B → C をもう一度。
3. 「ログをコピー」でフィードバックに貼るか、ここに貼る。承認は自動（実験中はシートを出さない）。
読み方:
| 既定 | greedy | 判断 |
|---|---|---|
| ばらつく（n/5 が途中の値・崩れた文あり） | A・B・C とも 5/5 | H1。生成設定を greedy（または低温＋top-p）にすれば直る |
| C だけ低い | C だけ 0/5 | H2。履歴の渡し方（アダプター側）を調べる |
| A から低い | A でも低い | H3。モデルを大きくする（Qwen2.5 3B など）か、救済（ADR-028）を併用 |

#### 実験結果（ビルド 9、iPhone 15、フィードバック ADbZ1n-ApPfz、2026-10-20 22:40）
スクリーンショットに写っているのは **C（ツール保存の後）× 既定** の後半だけ。A・B と greedy の結果は未入手（ログ全文が要る）。
- 結果: `C / 既定: ツール呼び出し 0/5`。
- 1 ターン目（「私の名前はケイタ 覚えておいて」）: #3・#5 は save_note を呼んで保存。#4 は `.getName("ケイタ")` という本文を返し、ツールを呼ばなかった。
- 測定ターン（「牛乳を覚えておいて」）: 1 回もツールを呼ばない。返答は `メモを保存しました: 牛乳`（#5）、`getName("牛乳")`（#4）、空（#3）。
- 読み: 1 ターン目の最終返答は、ツール結果の文字列（「メモを保存しました: …」）をそのまま繰り返したもの。2 ターン目のモデルはその**返答の形をまねて**、ツールを呼ばずに「保存しました」と書いている。これはアンチゴール「保存していないのに保存したと見える」そのもの。ツール結果を含む履歴が 2 ターン目の失敗を招く（H2 寄り）。1 ターン目でも呼ばないことがある（H3 も残る）。H1（ランダム選択）は greedy の結果待ち。

ログ全文（フィードバック AGbDFO5rPRvu のコメント、同じ C × 既定の 1 回分）で分かった追加の事実:
- 1 ターン目の save_note 成功は 3/5（#2・#3・#5）。失敗の 2 回は、ツール呼び出しを**本文に書いた**: `(save_note, {"text": "ケイタさん、覚えておいて"})`（#1）、`.getName("ケイタ")`（#4）。Qwen の正式な `<tool_call>` 形式で出していないので、アダプターはツールとして扱わない（本文 JSON の救済 ADR-028 の対象になり得る形）。
- 測定ターンは、1 ターン目が成功しても失敗しても 0/5。#1 でも本文に `(save_note, {"text": "牛乳は、乳製品を指すことが多いです。"})` を書いた。#2 は牛乳についての長い説明文（4.3 秒）。
- A・B と greedy は未実行（ログに無い）。

#### 全部実行の結果（ビルド 11、iPhone 15 / iOS 27.0.1、フィードバック AG8gbTm_Yawg、2026-10-22）
各 5 回、毎回新しいセッション、自動承認。呼 = 測定ターン（「牛乳を覚えておいて」）でツールを呼んだ回数、偽 = 呼ばずに「保存」と書いた回数、文 = 呼び出しを本文に書いた回数、初 = C の 1 ターン目で保存できた回数。
| | 既定（温度 0.6） | greedy |
|---|---|---|
| A 1 ターン目 | 呼 4/5（文 1） | **呼 5/5** |
| B 雑談の後の 2 ターン目 | **呼 0/5** | **呼 0/5** |
| C ツール保存の後の 2 ターン目 | 呼 0/5（偽 1・文 1、初 2/5） | **呼 0/5（偽 5、初 5/5）** |
判断:
- H1（ランダム選択）は **1 ターン目だけ** 効く。greedy で 1 ターン目は 5/5 になり、崩れた本文も出ない。
- H2（ツール結果の履歴が原因）は **否定**。ツールを含まない雑談の後（B）でも 0/5。2 ターン目以降は履歴の中身に関係なくツールを呼ばない。
- greedy の C では 5 回とも「保存した」と書くだけ（偽 5）。保存していないのに保存したと見える（アンチゴール）。
- 残る説明は、このモデル（Qwen2.5 1.5B）が複数ターンの履歴があるとツールを呼ばない（H3）か、アダプターの 2 ターン目のプロンプトに問題がある、のどちらか。どちらかはまだ切り分けていない（大きいモデルでの比較、または 2 ターン目のプロンプトの確認が要る）。
- 項目 3（MLX で 1 ターン目のツール呼び出し）: **合格**（greedy）。項目 4（複数ターン）: **MLX では不合格**。

#### 実験 D: 毎ターン新しいセッション＋前の会話を文字で畳み込む（2026-10-22 追加）
目的: 2 ターン目でツールを呼ばない問題（上の B・C）を、Pocket Agent の Apple ローカルと同じ「畳み込み」（ADR-017）で避けられるか確かめる。通れば、ローカルモデルは会話をトランスクリプトで持たず、毎ターン 1 ターン目として送る設計にできる。
- D1: 雑談（「こんにちは。今日はいい天気ですね。」）を 1 つ目のセッションで送り、返答を得る。測定ターンは**新しいセッション**で、プロンプトを次の形にする。
  ```
  これまでの会話（参考。ここに書かれた操作は実行済みとは限らない）:
  ユーザー: こんにちは。今日はいい天気ですね。
  アシスタント: （1 つ目の返答）

  今回のユーザーの発言: 牛乳を覚えておいて
  ```
- D2: 1 つ目のセッションで「私の名前はケイタ 覚えておいて」（実際に save_note を呼ぶ）。測定ターンは同じ形で畳み込んだ新しいセッション。
手順（iPhone 15、`MLX Qwen2.5 1.5B`、先に「モデルを読み込む」）: 「ログを消す」→「D だけ実行（D1・D2 × 既定・greedy）」→ 終わったら「結果だけコピー（400字以内）」をフィードバックのコメントに貼る。
読み方: 結果の行は `D1g 呼n/5 偽n 文n`。D1・D2 の greedy が 5/5 に近ければ畳み込みで解決できる。偽が多ければ、畳み込んだ「保存しました」をまねている（畳み込む文から過去の操作結果を外す等を次に試す）。
