# 実機確認: 記録の整合性・削除・モデル・下書き

実機結果は未記入。CI成功はコンパイルと自動テストの証拠であり、以下の操作確認を代替しない。

## 1. 原文と要約
1. 日誌で「予算は10万円」を入力し、記録画面で「要約する」。
2. 原文を「予算は100万円」に変更。
3. 古い要約の警告が出て、通常の「保存」が無効になること。
4. 「原文のまま保存」で100万円が保存され、または再要約後に通常保存できること。
5. 要約のストリーム中に停止し、「途中で停止した要約」の表示が出ること。

## 2. 下書き
1. 日誌のテキスト入力欄へ入力し、アプリを終了・再起動。「下書きを再開」から同じ文章を開くこと。
2. 原文と要約を編集し「後で続ける」。再起動して両方の編集内容が残ること。再開操作だけではモデルの生成が始まらないこと。
3. 下書きを保存し、再起動して下書きが出ず、日誌が1件だけ増えること。
4. 下書きを破棄し、再起動して復活しないこと。
5. 下書きがある状態で設定から全データ削除し、入力欄と下書きが消えること。

## 3. 削除
1. 検証画面で測定ログを作り、クリア後に再起動してログがないこと。
2. 会話・日誌・下書き・ログを作り、設定で全データ削除。再起動して対象データがないこと。
3. ファイル削除失敗は自動テストの注入で確認する。失敗時に成功表示されず、他の削除を試みて再試行できること。

録音/チャット実行中の全削除と処理の一括停止は今回の完了対象外。並行セッションの統合後にアプリ全体のライフサイクルとして対応する。

## 4. モデル
1. 更新前にダウンロードした有効なQwenモデルが、更新後もダウンロード済みとなり、機内モードで読み込めること。
2. ダウンロードを中断し、完了前のファイルが読み込み可能と表示されないこと。
3. ダウンロードの停止直後にモデル削除を行い、書き込み終了後に削除されること。
4. 空/切断された重み、tokenizer不足、欠損シャードは実ファイルの小さなfixtureによる自動テストで確認する。
