# 文字起こし精度の物差し測定（2026-11-03）

目的: 文字起こしの性能アップに先立ち、現行方式（日誌・会議とも Apple SpeechAnalyzer）の誤り率を、実音声で測れる物差しを作る。以後のエンジン比較（Whisper 系・SenseVoice 系など）と整文の効果測定は、すべてこの手順の固定文と採点方法でそろえる。

前提:

- 使う文章は下記の固定文のみ（機微情報は入れない）。実機での確認は人が行う（AGENTS.md）。
- 実音声そのものはリポジトリに入れない。固定文の起こし結果テキストは機微でないので、記録として残してよい。
- 採点は `tools/cer.py`（文字誤り率 CER。句読点と空白は除いて数える。数字の表記ゆれ——「3千億」と「三千億」など——は誤りとして数えられるので、気づきメモに「表記ゆれ」と残す）。

## 固定文（このまま読み上げる）

### A. 読み上げ文（ニュース調。数字と固有名詞）

来月から、新しい半導体工場の建設が始まります。投資額は約三千億円で、二千二十八年の稼働を目指しています。完成すれば、国内で千二百人の雇用が生まれる見込みです。

### B. 独話メモ調（口語。日誌の想定）

明日の午前十時に、田中さんと打ち合わせがあります。先方から資料がまだ届いていないので、今日の夕方までに確認の連絡を入れます。帰りに、牛乳と卵と洗剤を買って帰ります。

### C. 会議・専門用語調

本日の議題は、露光装置の納期と、歩留まりの改善についてです。先週の測定では、線幅のばらつきが一部で規格を超えていました。原因の切り分けを来週までに行い、対策を報告してください。

## 手順

1. 静かな部屋で iPhone を机に置き、口元から約 30cm（日誌の想定）で、固定文 A〜C を日誌の音声入力で起こす。起こし結果は直さずにそのまま保存する。
2. 同じ A〜C を、約 1m（会議の想定）で会議モードで起こす（「会議の起こしが日誌より悪い」件の切り分けを兼ねる）。
3. 固定文をファイルに写し（reference）、起こし結果と 1 組にして採点する。

```bash
python3 tools/cer.py reference-A.txt journal-A.txt
```

4. 結果を下の記録表に書く。所要時間は、話し終わってから結果が確定するまでの体感でよい。

## 次の段階

同じ固定文・同じ距離で、候補エンジン（Whisper 系、SenseVoice 系など。比較用の他アプリでもよい）で起こし、CER をこの表に並べる。エンジンの差し替え判断は、その比較表で行う。整文（端末内モデルでの起こし文の修正）を入れた場合は、整文の前後で同じ音声の結果を採点し、改善幅を記録する。
