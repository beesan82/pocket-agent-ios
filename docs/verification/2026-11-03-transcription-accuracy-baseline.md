# 文字起こし精度の物差し測定（2026-11-03）

目的: 文字起こしの性能アップに先立ち、現行方式（日誌・会議とも Apple SpeechAnalyzer）の誤り率を、実音声で測れる物差しを作る。以後のエンジン比較（Whisper 系・SenseVoice 系など）と整文の効果測定は、すべてこの手順の固定文と採点方法でそろえる。

2026-11-04 の変更: 測定の主手順は、アプリ内蔵の自動チェック（合成音声をファイルから直接認識、ADR-044）に移った。自動チェックは音源が固定で再現性があるため、エンジン比較と整文の効果測定の回帰の物差しとして既定とする。実声での測定（下記「実声の物差し」）は実利用の精度を見るための正として残し、アプリ内の手動読み上げを補助手順、スクリプトでの採点をクロスチェックとする。合成音声の系列と実声の系列は混ぜない（ログ行の `src=synth` の有無で分ける）。

前提:

- 使う文章は下記の固定文のみ（機微情報は入れない）。実機での確認は人が行う（AGENTS.md）。
- 実音声そのものはリポジトリに入れない。固定文の起こし結果テキストは機微でないので、記録として残してよい。
- 採点は `tools/cer.py`（文字誤り率 CER。句読点と空白は除いて数える。数字の表記ゆれ——「3千億」と「三千億」など——は、ADR-046 以降は採点前に正規化して数えない（新系列。旧系列の値と再現方法は下記））。

## 固定文（このまま読み上げる）

### A. 読み上げ文（ニュース調。数字と固有名詞）

来月から、新しい半導体工場の建設が始まります。投資額は約三千億円で、二千二十八年の稼働を目指しています。完成すれば、国内で千二百人の雇用が生まれる見込みです。

### B. 独話メモ調（口語。日誌の想定）

明日の午前十時に、田中さんと打ち合わせがあります。先方から資料がまだ届いていないので、今日の夕方までに確認の連絡を入れます。帰りに、牛乳と卵と洗剤を買って帰ります。

### C. 会議・専門用語調

本日の議題は、露光装置の納期と、歩留まりの改善についてです。先週の測定では、線幅のばらつきが一部で規格を超えていました。原因の切り分けを来週までに行い、対策を報告してください。

## 手順

### 主手順: アプリ内自動チェック（合成音声、ADR-044）

1. 検証画面 →「文字起こし精度チェック」で「自動チェック」を押す。A→B→C が自動で進み、各文の CER と認識テキストが表示される。
2. 結果を下の「自動チェックの記録」に書く。測定ログには `src=synth` 付きの行が残る（本文は残らない。ADR-026）。
3. 実機確認の観点の詳細は `docs/verification/2026-11-04-transcription-auto-check.md`。

### 補助手順: アプリ内手動読み上げ（実声）

1. 同じ「文字起こし精度チェック」の節で文を選び、録音 → 自分で読み上げ → 停止する。CER と認識テキストが表示され、測定ログの行は無印になる。
2. 採点ルールの突き合わせとして、画面の CER が、同じ起こし文に対する `tools/cer.py` の結果と一致することを確認する。

### 実声の物差し（従来手順。スクリプトでクロスチェック）

1. 静かな部屋で iPhone を机に置き、口元から約 30cm（日誌の想定）で、固定文 A〜C を日誌の音声入力で起こす。起こし結果は直さずにそのまま保存する。
2. 同じ A〜C を、約 1m（会議の想定）で会議モードで起こす（「会議の起こしが日誌より悪い」件の切り分けを兼ねる）。
3. 固定文をファイルに写し（reference）、起こし結果と 1 組にして採点する。

```bash
python3 tools/cer.py reference-A.txt journal-A.txt
```

4. 結果を下の記録表に書く。所要時間は、話し終わってから結果が確定するまでの体感でよい。

判定: 代替候補の中に対象用語（露光装置・歩留まり・線幅・規格）が 1 件も現れず「不発」。エンジンが正解を候補にも持っていないため選び直しは成立しない。設計書の判断基準どおり**実験1は不採用**とし、実験2（用語辞書の後処理）へ進む。実験 ON/OFF の所要時間差は今回の測定では記録していない。

同じ固定文・同じ距離で、候補エンジン（Whisper 系、SenseVoice 系など。比較用の他アプリでもよい）で起こし、CER をこの表に並べる。エンジンの差し替え判断は、その比較表で行う。整文（端末内モデルでの起こし文の修正）を入れた場合は、整文の前後で同じ音声の結果を採点し、改善幅を記録する。

## アプリ内チェックのログ形式（2026-11-04 追記）

アプリ内の精度チェックは、測定ログに `cer.journal passage=A cer=0.123 ref=73 hyp=85` の形で残す（本文は残さない。ADR-026）。自動チェック（合成音声、ADR-044）の行は末尾に `src=synth` が付き、無印は実声の読み上げを示す。合成音声は実声より CER が楽に出るため、比較表ではこの印で系列を分けて扱うこと。

実験の ON 行は、標準の行の末尾に実験印を足した形にする（いずれも件数と CER のみで、本文・対象語は残さない。ADR-026 / ADR-047）。

- 実験1（代替候補の選び直し）ON: 標準行 + ` alt=on termerrors=<n>`（`termerrors` は ON 適用後の用語エラー数）
- 実験2（用語辞書の後処理）ON: 標準行 + ` dict=on termerrors=<n> corrections=<n>`（`corrections` は辞書の発動総数。A・B で 0 でない場合は過剰補正の兆候）
