# CER 採点への数字表記の正規化（漢数字↔算用数字）

## 目的

現行の採点（`tools/cer.py` と Core の `TranscriptionScorer` で同一ルール）は、漢数字と算用数字の違いを誤りとして数える。初回ベースライン（2026-11-04、合成音声）の A は CER 20.55% だったが、大半は認識の失敗ではなく数字の表記ゆれ（三千↔3000、二千二十八↔2028、千二百↔1200）だった。数字の多い文ほど CER が実態より悪く出て、精度改善の効果測定を誤らせる。採点前に漢数字と算用数字を同一の正規形へ寄せ、CER が「表記」ではなく「認識」を測るようにする。

これは物差しの定義変更である。変更後の採点は「新系列」とし、変更前の値（旧系列）は消さずに並記する（ベースライン文書の未決課題への回答。ADR-046）。

## 方針

- 正規化は現行 `normalize` の最終段に足す: Unicode NFKC → 空白・句読点の除去 → 数字表記の変換。参照文と認識文の両方に同じ変換をかける。
- `tools/cer.py` と `TranscriptionScorer` は同一ルールを保つ（片方だけ変えるのは禁止）。変換できない・曖昧な表記は無理に触らない。
- アプリ側（`TranscriptionScorer`）は常時変換する。`tools/cer.py` には旧系列を再現するための `--keep-numerals`（数字変換をしない）を足す。既存の `--keep-punct` は従来どおり NFKC のみで、数字変換もしない。

## 変換仕様

対象文字は、算用数字 `0-9`、漢数字（一二三四五六七八九）、零・〇、小単位（十・百・千）、大単位（万・億・兆）とする。これらの文字だけからなる最大の連なり（ラン）を 1 つの数表記として解釈し、10 進文字列（先行ゼロなし）へ置き換える。解釈できないランはそのまま残す。

### 単位を含まないラン

- 算用数字のみならその値（先行ゼロは落とす）。
- それ以外は、各文字が 1 桁に対応する「桁並び」として読む（〇・零は 0、漢数字はその桁、算用数字はそのまま）。
  - 例: 二〇二八 → 2028、一 → 1（「一部」が「1部」になる）。

### 単位を含むラン（文法解釈）

- 大単位（兆・億・万）は降順に最大 1 回ずつ現れる。その前は 1 万未満の節で、節が空であってはならない。単独の大単位は変換しない（「万一」「万歳」のような語を守る）。
- 節の中は `[数]千 [数]百 [数]十 [数]` の順で、小単位は降順に最大 1 回ずつ。単位の前に数が無い場合は 1 として扱う（千二百 = 1200、十 = 10）。末尾の数は、1 桁の漢数字か算用数字の連なりとする（例: `3000億` の 3000、`3千` の 3）。
- 〇・零を含むランは文法解釈をしない（桁並び読みと混ざる表記は曖昧なので触らない）。
- 単位の重複・順序違反・漢数字の不自然な連続など、規則に合わないランは変換しない。

### 変換例

| 入力 | 出力 | 備考 |
|---|---|---|
| 三千 | 3000 | |
| 二千二十八 | 2028 | |
| 千二百 | 1200 | 千の前の数は暗黙の 1 |
| 三千億 | 300000000000 | 正規形は単位なしの値 |
| 3000億 | 300000000000 | 認識側の表記と一致する |
| 一万二千 | 12000 | |
| 午前十時 | 午前10時 | 「時」は対象外の文字 |
| 一部 | 1部 | 漢数字 1 文字も変換する |

### 境界と割り切り

- 小数（3.5 など）は扱わない。小数点は現行どおり句読点として除かれる（現行挙動を変えない）。
- 単独の十・百・千は数として変換する（十時→10時 が狙い）。「千里」のような語の一部であっても、参照と認識の両方に同じ変換がかかるため、採点への影響は表記ゆれの解消方向にのみ働く。
- 単位のない漢数字の連続（二三など）は桁並びとして読む。語の一部である場合は割り切る。
- 扱う値は 9999 兆（約 10^16）までで、64 bit 整数に収まる。

## 系列の扱い

- 初回ベースラインの認識テキスト（2026-11-04 の実機結果として記録済みの A〜C）を新ルールの `tools/cer.py` で再採点し、新系列の参考値としてベースライン文書に追記する。旧系列の値は消さずに並記する。
- アプリ内チェックのログ行（`cer.journal` の `ref=` / `hyp=` の文字数）は、正規形への変換で変わる（例: 三千億 は 3 文字から 12 文字になる）。これも系列の区別として ADR とベースライン文書に明記する。

## 確認

- Swift: `TranscriptionScorerTests` に変換例のテストを足す（変換例の一致、数字を含まない文が不変であること、解釈できない表記が不変であること、固定文 A〜C の再採点値が Python と一致すること）。RED を PR の CI で確認してから実装し、GREEN を確認する。
- Python: `tools/test_cer.py` に同じ変換例のテストを置き、同一ケースを両実装で流して結果が一致することを確かめる。
- 実機確認は不要（採点ルールのみの変更で、認識そのものは変わらない）。アプリ内表示の CER は次回ビルドから新系列になる。
