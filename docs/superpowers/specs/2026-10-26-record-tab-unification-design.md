# 「記録」タブへの統合

日付: 2026-10-26

## 意図

日誌と会議は保存後に同じ記録として扱われ、チャットからも参照できる。入口を一つにして、普段のメモと会議の開始を迷わず選べるようにする。ユーザーは「日誌と会議って重複してない？ 分ける意味あるんかな」と問い、「記録」タブへの統合を選んだ。

## ゴール・範囲

- 下部タブを「記録」「チャット」の二つにする。
- 「記録」では、短い文字・音声メモを従来どおり素早く始められ、同じ画面から「会議を開始」できる。
- 保存済みの日誌・会議は現在の一覧・検索・詳細画面で一緒に扱う。
- 会議中は「記録」画面に状態と「会議に戻る」を表示する。チャットに移っても録音を続け、会議画面へ戻れる。
- 会議の録音、途中の要点更新、二言語対応、中断・再開、保存失敗時の再試行は維持する。

## 非ゴール・避けたいこと

- ホーム画面ウィジェット、ショートカット、共有拡張はこの変更に含めない。
- 保存形式の移行や記録の種類を示す新しいデータ項目は追加しない。
- 会議画面を閉じたりタブを切り替えたりしただけで録音を終了させない。
- 会議録音中に別の会議を開始できるようにしない。

## 検討した方法

1. **二つのタブを維持する**: 会議機能は見つけやすいが、同じ記録を扱う入口が二つ残る。
2. **「記録」タブへ統合する（採用）**: 一覧と入力を一つにし、長時間録音だけ専用画面へ進む。既存の `MeetingSession` と `JournalStore` を活用できる。
3. **日誌と会議の録音処理まで一本化する**: 内部は揃うが、短いメモと継続的な会議録音では状態と終了条件が異なり、今回の操作改善に対して変更が大きい。

## 画面と動き

1. 起動時の「記録」画面は現在の日誌一覧、検索、下書き再開、文字入力、短い音声入力を持つ。目につく位置に「会議を開始」を置く。
2. 「会議を開始」で会議専用画面へ進み、前回の言語設定で録音開始を試みる。音声データや権限の準備が必要なら、会議画面で理由と準備操作を示す。言語を先に変えたい場合は「会議の準備・言語」から従来の待機画面を開く。
3. 会議が準備中・録音中・中断中・保存中は、「記録」画面の上部に状態と「会議に戻る」を表示する。会議専用画面に戻って再開・終了できる。
4. 会議を保存したら同じ記録一覧に現れる。保存失敗時は会議専用画面で再試行できる。既存の保存済み記録はそのまま表示する。
5. 設定への導線は「記録」画面に残す。チャットの導線・内容は変えない。

## 実装上の制約・検証

- `RootTabView` のタブ構成を変更し、`JournalView` に会議画面への導線と進行中の状態を追加する。`MeetingSession` はアプリ全体で一つのまま、`MeetingView` を遷移先として使う。会議画面には記録画面からの初回表示時だけ自動開始する引数を追加する。
- 一覧の再読込は、会議保存後に「記録」へ戻った時にも反映する。保存処理と既存データ形式は変更しない。
- 確認する操作: メモの文字・音声保存、会議開始・保存、会議中にチャットへ移動して復帰、中断から再開、保存失敗から再試行、既存記録の表示・検索。
- Windows では iOS シミュレータを実行できないため、利用可能な静的確認と macOS CI のビルド・テストで検証し、実機の画面操作は未確認として報告する。

## 実装者に任せる細部

ボタンの配置・アイコン・短い状態文言、保存後の画面遷移の細部は、既存の SwiftUI 画面構成に合わせて決める。
