# 文字起こし精度をボタン一つで検証する

## 目的

「文字起こしが悪い」と感じても、現行方式の誤り率を測る手段がアプリ内に無く、検証には手順書（`docs/verification/2026-11-03-transcription-accuracy-baseline.md`）に沿った手作業と、結果をチャットへ貼る作業が必要だった。検証をボタン一つで始められ、その場で誤り率（CER）が出るようにして、エンジン比較と整文の改善を数字で回せるようにする。

## 方針

- 既存の検証画面に「文字起こし精度チェック」の節を足す。固定文 A〜C（手順書と同じ文）をアプリ内に持ち、1 件ずつ「文を表示 → 録音して読み上げ → 自動で採点」を繰り返す。
- 採点は Core の `TranscriptionScorer` が行い、`tools/cer.py` と同じ規則（NFKC 正規化、句読点と空白を除いた文字誤り率）でそろえる。画面には CER と起こし結果そのものを出す。
- 結果は測定ログに `cer.journal passage=A cer=0.123 ref=88 hyp=85` の形で残す。本文は残さない（ADR-026 の方針どおり、ログは件数と測定値のみ）。音声は保存しない。
- 対象は日誌の音声入力経路（`SpeechCapture`）。会議経路は録音まわりの条件が違うため、この画面では扱わない（`docs/phase0-checklist.md` の手作業項目として残す）。

## 検討した方法

- **検証画面に専用の節を足す（採用）:** 既にある `SpeechCapture` と測定ログを再利用でき、実機での検証がボタン起点になる。
- **日誌画面に組み込む:** 日常の入力と検証が混ざり、誤操作で実日誌を汚す恐れがある。
- **外部スクリプトのまま（現行の手順書方式）:** アプリの外の作業が残り、ボタン一つにならない。物差しの定義としては残し、アプリ内の採点と規則をそろえる。

## 確認

- Core の採点は、`tools/cer.py` で検証済みの既知の組（同一文で 0、置換と欠落で 2/9、数字の表記ゆれで 1/10）でテストする。
- 実機では、日誌経路で A〜C を読み上げ、画面の CER と、同じ結果を `tools/cer.py` で採点した値が一致することを確認する（手順は `docs/verification/` に追記する）。
