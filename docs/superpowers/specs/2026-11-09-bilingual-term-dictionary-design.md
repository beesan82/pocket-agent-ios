# 設計: 二言語経路への用語辞書の適用（ADR-048）

日付: 2026-11-09
関連: ADR-047（専門用語対策・用語辞書の本採用）、`docs/phase0-checklist.md` の未検証項目「二言語経路の確定テキストには未適用」

## 背景

用語辞書（`TermCorrector`、実験 2）は PR #12 で単言語ライブ経路に本採用され、実機測定で専門用語エラー 4 → 0 を達成した。しかし二言語経路（日本語＋英語など 2 言語の会議）は確定処理を単言語経路と共有していない:

- 単言語: `SpeechCapture.consume` が final 結果ごとに `SpeechCapture.correctFinalText` を適用する。
- 二言語: `SpeechCapture.report` が final 結果を `.candidate` として流し、`MeetingSession` が `LanguageArbiter` の言語判定を経てセグメント化する。辞書は一切かからない。

ADR-047 はこの組み合わせを「相互作用は別途設計」と記録し、チェックリストに未適用として残していた。本設計がその別途設計である。

## 設計判断: 適用点は「言語判定の後、セグメント化の時点」

`MeetingSession.accept(_:)` で、受理された候補を `TranscriptSegment` にする時点で補正する。

### この適用点にする理由

1. **言語判定への影響ゼロ**: `LanguageArbiter` は生の認識テキストで判定する（信頼度の文字数重み付け、`ScriptGuess` の文字種判定とも従来どおり）。補正ペアはすべて同字数（路行装置→露光装置、ぶどまり→歩留まり、企画→規格、先幅→線幅）だが、設計として「判定は生テキスト」を保証する方が、辞書にペアが増えても判定挙動が変わらない。
2. **受理されたテキストだけが補正される**: 判定で落とされた候補（rejected）はどこにも表示・保存されないため、補正する必要がない。表示・保存・翻訳・要点の入力になるのは受理セグメントだけであり、その単一の生成点で補正すれば全ての下流（翻訳ソース、要点入力、保存文）が一貫して補正済みになる。
3. **検証画面（二言語ゲート、段階 A）は対象外のまま**: ゲートは認識器と判定器の生の挙動を測る物差しであり、補正を入れると測定が変わる。実経路（会議）だけに適用する。

### 適用条件

- 候補の言語が `ja` のときだけ補正する。辞書は日本語認識の誤りを直すものであり、英語・中国語レーンのテキストは日本語認識器の出力ではない（中国語レーンには同じ漢字列が正当に出うる）。
- final（受理セグメント）にだけ適用する。`laneVolatile`（暫定表示）は単言語経路と同様に素通し。
- 補正ロジックは新設せず、単言語経路と同じ入口 `SpeechCapture.correctFinalText`（= `TermCorrector.correct`）を使う。ペア・条件・ペア単位 OFF の意味は両経路で同一。
- 発動件数は二言語経路では保持しない。単言語経路の `SpeechCapture.termCorrectionCount` は検証画面の 30 秒テストのログ行という読み手があるが、会議経路には対応する表示・ログが無い。必要になったら読み手と一緒に足す。

## テスト（TDD）

App 単体テスト `BilingualTermCorrectionTests` を先に書く（既存 API だけで書け、失敗はアサーションのみ）:

- 受理された日本語候補（固定文 C の実測誤文）が補正済みセグメントになる。
- 翻訳の入力が補正済みテキストである（補正が翻訳より前にかかる）。
- 英語候補は無変更。
- 「企画」の通常用法（企画を立てる）は二言語経路でも無変更。
- ja/zh ペアで中国語レーンは無変更（ja ゲートの固定）。
- laneVolatile は無変更（final のみ補正の固定）。
- 言語判定で負けた日本語候補は、補正されて復活したりしない（rejected のまま）。

RED は一時 PR で CI 失敗を確認し、GREEN は PR の CI 全ステップ成功で確認する（AGENTS.md の手順）。

## 実機確認

CI では実認識は検証できない。TestFlight 配信後に iPhone 15 で二言語会議を開き、日本語で固定文 C 相当を話してセグメントが補正されること、英語発話が無変更であることを目視する手順を `docs/phase0-checklist.md` の「実機で未検証」に残す。

## 影響範囲

- 変更: `MeetingSession`（適用点＋入口の静的関数）、`SpeechCapture`（コメントのみ、挙動変更なし）、テスト追加、ADR-048、チェックリスト。
- 変更なし: `TermCorrector` 本体、単言語経路の挙動、`LanguageArbiter`、検証画面の自動チェックと二言語ゲート。
